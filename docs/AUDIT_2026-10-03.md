# Audit — 2026-10-03

## Conclusion

The repository is structurally coherent, but the peer-data layer is **not yet ready to be treated as fully verified scoring input**.

The audit found:

1. all 23 portfolio companies have a peer dataset;
2. the no-live-execution boundary remains intact;
3. GitHub tests validate structure and basic gates;
4. several companies have enough aligned peer observations for one or more metrics;
5. many companies still have too little comparable data for a full 70% weighted Fundamental Quality score;
6. two factual/period errors were identified and corrected in this audit;
7. calculation-provenance formatting is not yet fully uniform across older peer files;
8. the configured peer method says `robust_peer_zscore`, while the current normalization code uses arithmetic mean and population standard deviation with z-score clipping. This methodology mismatch must be resolved before production scores are published.

## Corrected factual errors

### Skyward (peer of PLMR)

The dataset had 89.5% stored as an H1 combined ratio.

The official Q2 2026 release shows:
- Q2 total combined ratio: 89.5%
- H1 2026 total combined ratio: 90.0%

The H1 peer value is now corrected to 90.0%.

### Huntsman (peer of EMN)

The dataset had Q2 2026 revenue growth calculated using a rounded prior-year value of $1.5bn.

The official releases give:
- Q2 2026 revenue: $1,663m
- Q2 2025 revenue: $1,458m

Correct growth:

```
(1663 / 1458 - 1) * 100 = 14.060357%
```

The peer value is now corrected.

## Methodology issue to resolve

`config/peer_universes.yaml` currently says:

```
method: robust_peer_zscore
```

but `normalization.py` currently calculates:

```
z = (target - peer_mean) / population_standard_deviation
```

and clips the resulting z-score.

Those are not the same method.

Before any production Fundamental Quality values are written, choose and document one of:

1. standard mean/std z-score with clipping; or
2. robust median/MAD z-score with a defined fallback for zero MAD.

Until that is resolved, Fundamental Quality should remain unpublished.

## Provenance consistency issue

Several older `*_pct` fields store values in percentage points while their human-readable calculation strings omit an explicit `* 100`. The numeric values may still be correct, but the audit trail is ambiguous. Calculation expressions should be normalized before production scoring.
