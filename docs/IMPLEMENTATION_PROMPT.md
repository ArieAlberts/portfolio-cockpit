# Implementation prompt for coding agent

Use this repository as the starting point for Portfolio Cockpit.

## Permanent safety requirement

This repository is decision-support only.

**Never implement live brokerage order placement, modification or cancellation.**

No information selected, synthesized, scored, inferred or generated by the repository may directly trigger a live broker action.

Permitted:
- read-only broker account/position access
- market-data access
- backtests
- simulation
- paper trading
- proposed order tickets for human review

Forbidden:
- any live order endpoint
- any live order submit function
- any live cancel/replace function
- a config switch that enables live trading
- using a signal/score threshold as authorization to trade
- moving from paper to live automatically

If a future request conflicts with this invariant, preserve the invariant.

## Fundamental objective

Implement five separate concerns:

1. Fundamental Quality
2. Quality Drift
3. Valuation
4. Data Confidence
5. Portfolio Risk

Never use a single variable for multiple meanings.

### Fundamental Quality
- Scale: 0–100.
- 50 = median of relevant peer/company-type group.
- Sector/company-type normalized.
- Market-price changes alone never change this score.

### Quality Drift
- Every company receives an immutable starting baseline.
- Score at baseline is exactly 50.0.
- >50 = fundamental improvement versus its own baseline.
- <50 = fundamental deterioration versus its own baseline.
- Market-price changes alone never change this score.

### Valuation
- Scale: 0–100.
- Higher score = more attractive valuation.
- Independent of Fundamental Quality.

### Data Confidence
- Scale: 0–100.
- Track completeness, source quality, freshness and consistency.
- If below 80, downstream decision state must be DATA_CHECK.

### Portfolio Risk
- Separate from fundamental scores.
- Support configurable scenario shocks.

## Minimum execution-boundary tests

Tests must prove:
1. no class exposes a live-order submission method,
2. proposed trades remain data objects only,
3. IBKR integration is read-only or paper-only,
4. no environment variable can enable live execution,
5. no score or signal can invoke a live broker action.
